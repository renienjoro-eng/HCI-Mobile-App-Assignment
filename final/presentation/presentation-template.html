Introduction

  • Mobile app prototype for university students
  • Brings course registration, fees, results and profile into one place
  • Designed with HCI principles
  • Prototype built with Balsamiq; managed with GitHub
Speaker notes: emphasize that this is a design prototype, not a coded application.

Problem Statement

  • Students struggle to access scattered academic and admin services
  • Complicated interfaces cause delays and confusion
  • Smartphone-first users need a single, simple portal

Project Objectives

General

Design a user-friendly mobile app that simplifies access to university services through a centralized interface.

Specific (selected)

  • Simple course registration flow
  • Easy fee statement and results access
  • Profile management with clear feedback
  • User-centered design and usability testing

Target Users

Primary Users

All university students needing daily services.

New Students

Need orientation to university systems.

Continuing Students

Use the portal regularly for routine tasks.

User Research

  • How students currently access services
  • Common difficulties and pain points
  • Preferred navigation and feedback patterns
  • Dashboard expectations

User Persona 1 — The New Student

Goals

  • Find services easily
  • Register without confusion
  • Check fees and results

Needs

  • Simple navigation
  • Clear instructions
  • Confirmation after tasks

Pain points: complicated interfaces, hard-to-locate services, uncertainty about success.

User Persona 2 — The Continuing Student

Goals

  • Quick course registration
  • Fast results and fee checks
  • Profile management

Needs

  • Fast access to frequent services
  • Clear dashboard
  • Reliable feedback

Pain points: time-consuming processes, complicated navigation, difficulty locating info.

User Journey

Open App→ Login→ Dashboard→ Select Service→ Complete Task→ Feedback→ Dashboard

Task Flows

Course Registration

Login→Dashboard→Courses→Select→Confirm

Fee Statement / Results / Profile

Login→Dashboard→Service→Review→Dashboard

Usability Testing Plan

  • 5+ representative users
  • Task completion, navigation, errors
  • Label clarity and ease of use
  • Revise prototype based on findings

Usability Testing Findings

Successes

  • Tasks completed
  • Clear labels
  • Feedback understood

Problems

  • Navigation issues
  • Error-prone steps
  • Unclear controls

Speaker notes: summarize observations and link each issue to a design change.

Design Iterations

Sketches→Prototype→Walkthrough→Testing→Improve→Better Prototype

Focus: navigation, IA, button placement, feedback, error prevention, touch, consistency.

Final Prototype

  • All design iterations applied
  • Usability findings addressed
  • Final Balsamiq screens ready
  • Presentation and final report prepared

Limitations

  • HCI prototype, not production software
  • No real database or payment integration
  • No live examination or authentication systems
  • Demonstrates UI and interaction only

Future Improvements

  • SIS integration and secure auth
  • Real-time results and fee updates
  • Online payment and push notifications
  • Accessibility and additional usability testing

Conclusion

The University Student Portal Mobile App applies Human–Computer Interaction principles to deliver a centralized, intuitive, and accessible student experience.
